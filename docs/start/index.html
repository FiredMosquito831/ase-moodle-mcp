Șase pași, aproximativ cinci minute

Primii pași

De la zero la prima întrebare. Pașii de mai jos presupun Python 3.10+ și un cont BL@ASE pe online.ase.ro.

> Pașii

  1. Instalează pachetul

    Cu pipx, fără Node.js. Variantele npm și pip sunt în pagina de instalare.

    python -m pip install --user pipx
pipx install git+https://github.com/FiredMosquito831/ase-moodle-mcp.git

  2. Loghează-te o singură dată

    Se deschide o fereastră cu un profil dedicat. Te loghezi cu Google; tokenul se salvează în seiful sistemului.

    ase-moodle login

  3. Configurează clienții

    install scrie configurația în Claude Code, Codex, opencode și Antigravity. Pentru un singur folder, adaugă --scope project.

    ase-moodle install

  4. Verifică

    doctor verifică fiecare platformă, tokenul, procesele MCP și funcțiile Moodle. Fără token, pasul e skipped, nu eroare.

    ase-moodle doctor

  5. Întreabă în client

    Deschide Claude Code, Codex, opencode sau Antigravity și întreabă: „Ce termene am în următoarele 7 zile?”. Serverul ar trebui să apeleze deadlines.

  6. Descarcă un semestru

    Materialele ajung în folderul dat, cu index.md, teme.md, forumuri/, quizuri.md, note.md și datele brute. A doua rulare sare fișierele existente.

    ase-moodle download --year 3 --sem 1 --out D:\Materiale

> Ce instalează fiecare client

ClientGlobalDoar un folder
Claude Codeplugin + marketplace, scope userplugin + marketplace, în .claude/settings.json
Codexplugin + marketplace, în ~/.codexdoar serverul MCP, în .codex/config.toml
opencodeMCP + SKILL.md în ~/.config/opencodeMCP în opencode.json din folder
AntigravityMCP + plugin, prin agynu are: rămâne global

> Ce se întâmplă la login

Diagramă: login-ul deschide un profil de browser dedicat; te loghezi cu Google; Moodle redirecționează către moodlemobile://token=…; tokenul e verificat și salvat în Credential Manager sau Secret Service.

> Ce vezi dacă merge

ase-moodle auth-status întoarce logged_in și numele tău. ase-moodle doctor arată ok pentru pachet și pentru fiecare platformă instalată. În client, serverul apare ca ase-moodle și răspunde cu date reale.

Dacă doctor arată skipped pentru o platformă, CLI-ul acelei platforme nu e instalat sau nu e în PATH. Nu e o eroare: install marchează la fel platformele pe care nu le găsește.

Dacă doctor arată error, rulează din nou ase-moodle install pentru platforma respectivă. Instalarea e idempotentă: o rulare repetată nu dublează nimic, iar schimbarea de scop curăță celălalt scop.

Prima fereastră de login

Fereastra se deschide cu un profil de browser separat, nu cu profilul tău obișnuit. Loghează-te cu Google în ea. Dacă o închizi din greșeală, rulează din nou ase-moodle login; comanda așteaptă până la 300 de secunde.

Scope-ul de proiect

Dacă instalezi cu --scope project, pornește clientul din folderul exact unde ai instalat. Scope-ul de proiect nu se aplică în subfoldere; pentru asta folosește scope-ul global.

> Dacă ceva nu merge

Începe cu ase-moodle doctor și ase-moodle auth-status: ele spun ce e instalat, ce token există și de unde e citit. Lista completă de erori și rezolvări este în probleme frecvente.
