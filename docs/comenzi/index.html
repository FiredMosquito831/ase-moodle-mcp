37 de comenzi, generate din parser

Comenzi

Toate comenzile scriu JSON pe stdout, iar erorile merg pe stderr ca {"error": "...", "message": "..."}. Tabelul de mai jos este generat din parserul real: numele, opțiunile și ajutorul vin din cod. Aici găsești comenzi CLI ase-moodle pentru același cont Moodle ca uneltele MCP.

> Cum citești tabelul

N înseamnă un număr întreg, JSON un obiect JSON, iar A|B o alegere dintre valori. Opțiunile fără valoare sunt comutatoare. Comenzile care modifică contul cer --yes.

Textul pentru submit-text, reply și new-discussion vine din --text, dintr-un --file sau din stdin, prin pipe.

Coloana „Ce face” din pagina românească afișează textele de ajutor ale comenzilor, exact cum le dă --help. Pagina engleză le traduce, iar numele și opțiunile rămân aceleași.

> Coduri de ieșire

CodÎnseamnă
0reușit
1eroare: Moodle, token lipsă, fișier inexistent, ciorne dezactivate
2scriere blocată: lipsește --yes
3install, update sau doctor a găsit o problemă

> Scopuri și harness-uri

Comenzile claude, codex, opencode și antigravity merg doar la adaptorul lor. Fiecare acceptă install, update, uninstall și doctor, cu --scope global|project unde există. Antigravity nu are scop de proiect: --scope project este o eroare.

ase-moodle install fără nume de harness rulează toate adaptoarele. Un harness care nu suportă scopul cerut este sărit, cu motivul în output.

Confirmarea

Fără --yes, o scriere se oprește cu codul 2 și nu trimite nimic. Adaugă --yes doar după ce ai verificat exact ce trimite comanda.
