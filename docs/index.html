> Ce este

ase-moodle are trei fețe care folosesc același token Moodle. Serverul MCP ase-moodle-mcp vorbește prin stdio cu clientul tău. CLI-ul ase-moodle scrie JSON pe stdout, pentru scripturi. Pluginul adaugă în Claude Code, Codex, opencode și Antigravity uneltele, skill-ul și comenzile.

Nu ai nevoie de un cont separat și nu se instalează un server undeva. Totul rulează pe calculatorul tău, iar singurele conexiuni sunt către Moodle-ul configurat și, la instalare, către GitHub. Cu alte cuvinte, ase-moodle este un server MCP pentru Moodle: automatizare Moodle în agentul tău, cu confirmare pentru fiecare scriere.

> Pentru cine

Pentru studenții BL@ASE care vor să întrebe în limbaj natural: „ce am de făcut săptămâna asta?”, „descarcă materialele de la anul 3, semestrul 1”, „ce notă am la seminar?”. Agentul alege unealta potrivită și îți arată rezultatul.

Pentru cine lucrează din terminal: CLI-ul întoarce JSON, deci poate fi pus într-un script sau într-un pipeline fără să parseze text.

> Ce poți face

  • Cursuri și materiale

    Listezi cursurile pe an, semestru și tip. Descarci un curs sau un an întreg, în paralel: fișiere, pagini, linkuri, teme, forumuri, quizuri, note.

  • Teme și ciorne

    Vezi cerința, termenul, starea trimiterii și feedbackul. Trimiterea cere confirmarea ta, iar temele fără ciorne sunt protejate.

  • Forumuri

    Citești discuțiile și postările. Răspunsurile și discuțiile noi se trimit doar după ce aprobi textul.

  • Note

    Notele tuturor cursurilor, sau elementele de notare ale unui curs, cu feedback.

  • Quizuri

    Citești întrebările, salvezi răspunsuri fără să trimiți, apoi trimiți încercarea doar după o a doua aprobare.

  • Notificări și termene

    Notificările noi și termenele următoare, în ordine. Marcarea ca citită cere confirmare.

> Cum se leagă piesele

Diagramă: Claude Code, Codex, opencode și Google Antigravity pornesc serverul ase-moodle-mcp prin stdio; serverul apelează Moodle BL@ASE prin HTTPS; CLI-ul ase-moodle folosește același token.

> Cum funcționează

Te loghezi o singură dată, în browser, cu Google. Tokenul Moodle ajunge în seiful sistemului (Credential Manager pe Windows, Secret Service pe Linux), nu în fișiere de proiect.

ase-moodle install scrie configurația fiecărui client. Serverul citește tokenul la pornire și nu îl primește prin client.

Fiecare unealtă are o anotare: citire, scriere sau local. Scrierile cer confirm=true în MCP sau --yes în CLI; fără ele, acțiunea se oprește.

Descărcarea scrie totul într-un folder obișnuit, cu rezumate în Markdown și datele brute în _raw. Fișierele cu aceeași dimensiune sunt sărite, deci o rulare repetată nu descarcă din nou.

Serverul nu ține o copie a datelor tale. Fiecare apel citește din Moodle în momentul cererii, iar descărcarea scrie doar pe disc, în folderul pe care îl alegi.

> Ce primești

  • Un server MCP cu 28 de unelte, 4 prompturi și 2 resurse.
  • Un CLI cu 37 de comenzi, cu ieșire JSON pe stdout.
  • Un plugin pentru Claude Code, Codex, opencode și Antigravity.
  • Un skill care îi spune agentului ce are voie să facă și ce cere confirmare.

> O ieșire reală

Scrierile cer confirmarea ta

O trimitere, un răspuns pe forum sau un quiz pornit nu pleacă fără confirm=true (MCP) sau --yes (CLI). Aprobarea pentru o acțiune nu o acoperă pe următoarea.

> Trei întrebări dese

Merge cu contul meu?

Da, dacă ai un cont BL@ASE pe online.ase.ro. Login-ul se face cu Google, ca în browser.

Unde ajunge tokenul?

În seiful sistemului: Credential Manager pe Windows, Secret Service pe Linux. Nu în git și nu în mesaje de eroare.

Pot trimite teme fără să văd ce pleacă?

Nu. Fiecare scriere cere confirmarea ta, iar temele fără ciorne sunt refuzate implicit.
