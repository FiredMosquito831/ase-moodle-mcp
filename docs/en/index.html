> What it is

ase-moodle has three faces that share one Moodle token. The ase-moodle-mcp MCP server speaks over stdio to your client. The ase-moodle CLI writes JSON on stdout, for scripts. The plugin adds the tools, the skill and the commands to Claude Code, Codex, opencode and Antigravity.

You do not need a separate account, and no server is installed somewhere else. Everything runs on your machine, and the only connections are to the configured Moodle and, during installation, to GitHub.

> Who it is for

For BL@ASE students who want to ask in plain language: “what do I have to do this week?”, “download the year 3, semester 1 materials”, “what grade do I have in the seminar?”. The agent picks the right tool and shows you the result.

For people who work from a terminal: the CLI returns JSON, so it can go into a script or a pipeline without parsing text.

> What you can do

  • Courses and materials

    List courses by year, semester and type. Download one course or a whole year, in parallel: files, pages, links, assignments, forums, quizzes, grades.

  • Assignments and drafts

    See the requirement, the deadline, the submission state and the feedback. Submitting needs your confirmation, and assignments without drafts are protected.

  • Forums

    Read discussions and posts. Replies and new discussions are sent only after you approve the text.

  • Grades

    Grades for every course, or the grade items of one course, with feedback.

  • Quizzes

    Read the questions, save answers without submitting, then finish the attempt only after a second approval.

  • Notifications and deadlines

    New notifications and upcoming deadlines, in order. Marking one as read needs confirmation.

> How the pieces connect

Diagram: Claude Code, Codex, opencode and Google Antigravity start the ase-moodle-mcp server over stdio; the server calls BL@ASE Moodle over HTTPS; the ase-moodle CLI uses the same token.

> How it works

You sign in once, in a browser, with Google. The Moodle token goes into the system keychain (Credential Manager on Windows, Secret Service on Linux), not into project files.

ase-moodle install writes each client's configuration. The server reads the token at startup and never receives it through the client.

Every tool carries an annotation: read, write or local. Writes need confirm=true in MCP or --yes in the CLI; without it, the action stops.

Downloading writes everything into an ordinary folder, with Markdown summaries and the raw data in _raw. Files of the same size are skipped, so a repeated run downloads nothing again.

The server keeps no copy of your data. Every call reads from Moodle at request time, and downloading writes only to disk, in the folder you choose.

> What you get

  • An MCP server with 28 tools, 4 prompts and 2 resources.
  • A CLI with 37 commands, with JSON output on stdout.
  • A plugin for Claude Code, Codex, opencode and Antigravity.
  • A skill that tells the agent what it may do and what needs confirmation.

> A real output

Writes need your confirmation

A submission, a forum reply or a started quiz does not go out without confirm=true (MCP) or --yes (CLI). Approval for one action does not cover the next.

> Three common questions

Does it work with my account?

Yes, if you have a BL@ASE account on online.ase.ro. Login goes through Google, as in the browser.

Where does the token go?

Into the system keychain: Credential Manager on Windows, Secret Service on Linux. Not into git and not into error messages.

Can it submit assignments without showing me what goes out?

No. Every write needs your confirmation, and assignments without drafts are refused by default.
