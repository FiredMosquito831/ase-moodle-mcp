Troubleshooting

Always start with ase-moodle doctor and ase-moodle auth-status. They say what is installed, which token exists and where it is read from.

> Authentication

“The token is missing.” You have not run ase-moodle login, or the token was deleted. Run ase-moodle login.

Login times out (“No token received within the limit”). The window opened but you did not sign in. Run again, raise the time with ase-moodle login --timeout 600, or use --method manual.

“The browser for login is not installed.” The message contains the exact command, with the Python of the environment that runs ase-moodle. Run exactly that command, not some other python from PATH. Alternatively, --method manual.

auth-status says the token does not work. The token was reset in Moodle or expired. Get a new one with ase-moodle login. To invalidate a token completely, reset it from Security keys.

The manual method does not find the token. On Linux install xclip, xsel or wl-paste. Check that you copied exactly the 32-character string, without spaces. For scripts, login --token-stdin reads the token from stdin.

> Installation

ase-moodle-mcp is not on PATH. The package is not installed, or the pipx executables folder is not on PATH. Run pipx install --force git+https://github.com/FiredMosquito831/ase-moodle-mcp.git, then pipx ensurepath, and open a new terminal.

pipx install fails on Windows with “Access denied” on ase-moodle-mcp.exe. An MCP client is running and locks the executable. Close Claude Code, Codex, opencode or Antigravity and run again. doctor counts the running processes.

Claude Code does not see the update. Restart Claude Code: the plugin loads at startup.

Claude Code does not detect the server in the project folder. Restart Claude Code in the project folder, run /mcp, then ase-moodle claude doctor --project-dir <folder>. Check .claude/settings.json: it must contain ase-moodle@ase-moodle-marketplace in enabledPlugins. If Claude Code asks to approve the marketplace, accept.

Codex does not load the project server. Codex requires the folder to be marked as a trusted project. Also check that .codex/config.toml contains [mcp_servers.ase-moodle].

opencode.json is not valid JSON. The installer stops and leaves the file alone. Fix the commas and quotes, then run again. A .bak copy from the previous run exists.

Two ase-moodle servers appear in the client. You have an old global install and a project one. Run ase-moodle install <platform> --scope <wanted scope>: the other scope is cleaned automatically, so two servers with the same name do not exist.

> Writes and quizzes

needs_confirmation (exit code 2). The write has no confirmation. If you run the command, add --yes after checking what it sends. If an agent runs it, ask it to show the content and approve it.

“The assignment has no drafts.” Saving would send the file at once. Choose a final submission with --submit, or --allow-direct only if you want the direct save.

Quiz: “Unknown fields.” The names in quiz-answer do not match the ones from quiz-questions. Copy the names exactly from the answer.

Quiz: “The attempt could not be started.” The quiz is closed or you reached the attempt limit. The Moodle message explains.

> Downloads and doctor

Missing materials. Run again: files of the same size are skipped, missing ones are downloaded. Check _rezumat.json for errors and warnings.

doctor shows functii Moodle with a warning. obligatorii lipsa means the site no longer has the listed functions, usually after a Moodle update; the tools that use them will fail. optionale lipsa alone is not a problem: the package has a fallback or skips that material type.

Where are the logs? The package writes no log files. Errors appear on stderr (CLI) or in the tool's answer (MCP).

When it is not clear

Run ase-moodle doctor and keep the output: it does not contain the token. With it, the problem is usually easy to find.
