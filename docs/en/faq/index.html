Frequently asked questions

The answers below come from the product documentation and the code. The same answers appear in the page's structured data. The ase-moodle FAQ page covers the account, the token, safety, platforms and limits.

> About the product

How much does it cost?

Nothing. The code is under the Apache License 2.0, and the package installs from GitHub or npm. There is no subscription and no separate account.

Which account does it work with?

With a BL@ASE account on online.ase.ro. Login goes only through Google, as in the browser; there is no username-and-password login for the package.

Do I give the Google password to the package?

No. You sign in yourself, in the window that opens. The package never stores the Google password, not in the keychain, not in .env, not in files.

Where does the Moodle token go?

Into Windows Credential Manager or Secret Service on Linux. If the keychain is unavailable, it stays in ~/.ase-moodle/config.json, readable only by you. It never goes into git.

Does the token appear in the output?

No. auth-status and doctor only say where it was read from: env, dotenv, keyring or file. Errors do not include the token.

Does it send data to other servers?

No. The only connections are to the configured Moodle and to GitHub, only during installation, for the marketplace. There is no analytics and no telemetry.

> About writes

Can it submit assignments without my approval?

No. Writes need confirm=true in MCP or --yes in the CLI. Without them, the action stops with needs_confirmation (exit code 2) and sends nothing.

What happens on an assignment without drafts?

Saving would send the file at once. The package checks drafts_enabled and refuses with DirectSubmissionBlocked, without writing anything. Only allow_direct=true (or --allow-direct) forces it.

Can it answer quizzes?

Yes, because the student asked for it. The flow saves the answers first, without submitting, and finishes the attempt only after a second approval. Finishing is irreversible.

Which integrity rules apply?

The course rules. Many courses forbid automated help or outsourcing answers. The student is responsible for what is submitted.

> About platforms

Does it work on Linux and macOS?

Windows is tested on the real account. The installer logic is tested on Linux (WSL Ubuntu 24.04) and in CI. macOS is untested, apart from the server smoke test in the PyPI workflow.

Do I need Node.js?

No, if you use pipx. Node.js 18+ is needed only for the npm path. Both paths install the same Python package.

Does it work with another Moodle instance?

The package is written for BL@ASE, which runs Moodle 4.5 as of October 2026, and works on 4.5 and 4.1. Other instances might work, but they are untested.

Can I use it without a global install?

Yes, with npx ase-moodle-mcp <command> after npm. For MCP clients you need a fixed ase-moodle-mcp command on PATH, so a global install.

> Limits

What does the package not do?

It does not read private messages (messaging is disabled on the site), does not change the password, does not modify account settings and does not run quizzes or assignments automatically. Everything starts from a command or an explicit call.

What is not tested?

An open quiz completed end to end on the real account; a real submission with drafts enabled; the real CLI commands on Linux; the npm launcher; macOS.

Can I download a single course?

Yes. ase-moodle download --course ID selects the course by id, and the option can be repeated for several courses. Without --course, the year, semester and type filters choose the courses.

How do I update the package?

With pipx: pipx install --force git+https://github.com/FiredMosquito831/ase-moodle-mcp.git, then ase-moodle update. With npm, the launcher does not update the Python package if it already exists, so update it separately. Restart Claude Code afterwards.

What exactly does doctor do?

It checks without changing anything: each platform, the project installs, the token source, .env, the running MCP processes, the package version and the Moodle functions the package uses. Exit code 3 if it finds a problem.

The token was exposed. What do I do?

Treat it as compromised and reset it in Moodle: Security keys, the “Moodle mobile web service” row, the reset button. The old token stops working, and the package needs ase-moodle login.

What happens to downloaded materials?

They stay on disk, in the chosen folder, and are not deleted automatically. The package does not run them: an executable file in the materials stays a file until you open it. Check before you do.

Can I use the package in two clients at once?

Yes. Each client starts its own ase-moodle-mcp process, and all of them read the same token. Before reinstalling, close the processes: doctor counts them, and on Windows a running process locks the executable.

Does it work without opening a browser?

Yes, with ase-moodle login --method manual: the login page opens, you copy the token from Security keys, and the package reads it from the clipboard. For scripts, --token-stdin reads the token from stdin.

What happens when Moodle is updated?

doctor compares the Web Service functions the package uses with the ones the site has. obligatorii lipsa means a tool will fail; optionale lipsa alone is not a problem, because the package has a fallback or skips that material type.

Where do I report a problem?

On GitHub Issues, with the output of ase-moodle doctor and the error message. The output does not contain the token. For a new feature, the steps are in docs/DEVELOPMENT.md.
