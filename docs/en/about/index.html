About ase-moodle

> Verified state

Verified on the real account, in October 2026: browser login (SSO) and storage in Credential Manager; courses, assignments, forums, notifications, deadlines, grades and quizzes (reading); downloading a year and semester, with a second run that downloads nothing.

At the same time: errors with no side effects (closed quiz, missing objects, missing file); the drafts guard, which refuses a save on an assignment without drafts without sending anything; install, check and uninstall on Claude Code, Codex and opencode, globally and per project, and on Antigravity, globally.

The tests pass on Windows. On Linux (WSL Ubuntu 24.04) they passed before the latest changes and were not rerun.

> Known limits

Moodle messaging is disabled on the site. The Web Service functions are those of the Moodle mobile service; what exists only in the web interface is not covered. Antigravity installs globally only. macOS is untested.

Not tested on the real account: update for every platform and a real submission with drafts enabled, because no such situations exist right now.

> How it is built

The code is split by module: client.py talks to Moodle, activities.py does the reads, actions.py the writes with confirmation, and quiz.py, materials.py and install.py cover the large parts. The CLI and the MCP server use the same functions.

The tests run without internet and without your account, against a fake Moodle server with synthetic data. CI runs on Windows and Ubuntu: pyflakes and the unittest suite.

The plugin brings the MCP server, the skill and the /ase-login, /ase-deadlines and /ase-download commands. The skill in src/ase_moodle/data/SKILL.md is the canonical source; ase-moodle sync-plugin copies it into the plugin, and the tests check that the two copies are identical.

The npm launcher is a thin wrapper: it starts the commands from the Python package and installs it through pipx on the first run. The npm package has its own version, separate from the Python version.

Two public workflows check every change: ci.yml runs the tests on Windows and Ubuntu, and pypi.yml builds the package at a tag and starts it on Windows, Ubuntu and macOS before publishing. This page has its own workflow, which runs the site check.

> Contributing

Report a problem or propose a change on GitHub Issues. For a new feature, the steps are in docs/DEVELOPMENT.md: the logic, the CLI, the MCP tool, the documentation and the tests.
