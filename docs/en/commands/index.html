Commands

Every command writes JSON on stdout, and errors go to stderr as {"error": "...", "message": "..."}. The table below is generated from the real parser: the names, options and help come from the code. All ase-moodle CLI commands cover the same Moodle account as the MCP tools.

> How to read the table

N means an integer, JSON a JSON object, and A|B a choice between values. Options without a value are switches. Commands that change the account need --yes.

The text for submit-text, reply and new-discussion comes from --text, from a --file or from stdin, through a pipe.

The Romanian page's “What it does” column shows the commands' help texts, exactly as --help gives them. The English page translates them, while the names and options stay the same.

> Exit codes

CodeMeaning
0success
1error: Moodle, missing token, missing file, drafts disabled
2write blocked: --yes is missing
3install, update or doctor found a problem

> Scopes and harnesses

The claude, codex, opencode and antigravity commands go only to their own adapter. Each accepts install, update, uninstall and doctor, with --scope global|project where it exists. Antigravity has no project scope: --scope project is an error.

ase-moodle install without a harness name runs every adapter. A harness that does not support the requested scope is skipped, with the reason in the output.

Confirmation

Without --yes, a write stops with exit code 2 and sends nothing. Add --yes only after you have checked exactly what the command sends.
