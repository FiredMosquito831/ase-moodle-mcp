Six steps, about five minutes

Quick start

From zero to the first question. The steps below assume Python 3.10+ and a BL@ASE account on online.ase.ro. The quick start with ase-moodle takes about five minutes, from the install to the first answer.

> The steps

  1. Install the package

    With pipx, no Node.js needed. The npm and pip paths are on the install page.

    python -m pip install --user pipx
pipx install git+https://github.com/FiredMosquito831/ase-moodle-mcp.git

  2. Sign in once

    A window opens with a dedicated profile. You sign in with Google; the token is saved in the system keychain.

    ase-moodle login

  3. Configure the clients

    install writes the configuration into Claude Code, Codex, opencode and Antigravity. For one folder only, add --scope project.

    ase-moodle install

  4. Verify

    doctor checks each platform, the token, the MCP processes and the Moodle functions. Without a token the step is skipped, not an error.

    ase-moodle doctor

  5. Ask in your client

    Open Claude Code, Codex, opencode or Antigravity and ask: “What deadlines do I have in the next 7 days?”. The server should call deadlines.

  6. Download a semester

    Materials land in the given folder, with index.md, teme.md, forumuri/, quizuri.md, note.md and the raw data. A second run skips existing files.

    ase-moodle download --year 3 --sem 1 --out D:\Materiale

> What each client gets

ClientGlobalOne folder
Claude Codeplugin + marketplace, user scopeplugin + marketplace, in .claude/settings.json
Codexplugin + marketplace, in ~/.codexonly the MCP server, in .codex/config.toml
opencodeMCP + SKILL.md in ~/.config/opencodeMCP in the folder's opencode.json
AntigravityMCP + plugin, through agynone: it stays global

> What happens at login

Diagram: login opens a dedicated browser profile; you sign in with Google; Moodle redirects to moodlemobile://token=…; the token is verified and saved in Credential Manager or Secret Service.

> What you see when it works

ase-moodle auth-status returns logged_in and your name. ase-moodle doctor shows ok for the package and for each installed platform. In the client, the server appears as ase-moodle and answers with real data.

If doctor shows skipped for a platform, that platform's CLI is not installed or not on PATH. It is not an error: install marks the platforms it cannot find the same way.

If doctor shows error, run ase-moodle install again for that platform. The install is idempotent: a repeated run duplicates nothing, and changing the scope cleans the other scope.

The first login window

The window opens with a separate browser profile, not your usual one. Sign in with Google inside it. If you close it by mistake, run ase-moodle login again; the command waits up to 300 seconds.

The project scope

If you install with --scope project, start the client from the exact folder where you installed. The project scope does not apply in subfolders; use the global scope for that.

> If something goes wrong

Start with ase-moodle doctor and ase-moodle auth-status: they say what is installed, which token exists and where it is read from. The full list of errors and fixes is in troubleshooting.
